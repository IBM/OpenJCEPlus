8. Test Method Pattern

All 14 new test methods follow the identical pattern already used for the 4 existing tests:

/** KAT: <ALG_NAME> - round-trip sign/verify with draft key pair. */
@Test
public void testKAT_<SUFFIX>() throws Exception {
    PublicKey pub  = loadPublicKey("<ALG_NAME>", PK_<SUFFIX>);
    PrivateKey priv = loadPrivateKey("<ALG_NAME>", SK_<SUFFIX>);
    byte[] newSig  = sign("<ALG_NAME>", MSG, priv);
    assertTrue(verify("<ALG_NAME>", MSG, newSig, pub),
            "Round-trip verify failed for <ALG_NAME>");
}
Why round-trip only (not reference-sig verify)? ML-DSA signing is randomised. The reference Python implementation uses a different RNG seed than OpenJCEPlus, so the draft's s byte sequence will never match byte-for-byte. The round-trip test fully exercises key-load + sign + verify paths using the draft's authentic key material.

10. Key Technical Notes

  • Base64url → standard base64: The JSON uses URL-safe base64 (- and _). All characters must be converted (-→+, _→/) and padding added before use as Java string literals.
  • pk field structure: pk = raw_mldsa_bytes ‖ raw_trad_bytes — a plain concatenation, no DER wrapper. The ML-DSA prefix length is fixed per level (1312 / 1952 / 2592 bytes).
  • sk_pkcs8 field: Contains only the traditional component in standard PKCS#8 form. The ML-DSA private key is not in the vectors. loadPrivateKey() wraps it in the composite PKCS#8 outer structure.
  • RSA public key in pk: The trad bytes are a full DER SubjectPublicKeyInfo (SEQUENCE { SEQUENCE { rsaEncryption, NULL }, BIT STRING { ... } }), not just the modulus. buildSpki() must not re-wrap these — it must use them as-is for RSA. Action required: verify loadPublicKey() handles RSA SPKIs correctly, or add a special case for RSA.
  • Checkstyle: 100-char line limit, no tabs, alphabetical import order, license header required, no wildcard imports.
